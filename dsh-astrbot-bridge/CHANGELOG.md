# 更新说明（CHANGELOG）

**接到 DSH** —— 让 AstrBot 把"需要动手"的活交给本机 DSH，回话仍由 AstrBot 自己说。

当前版本：**0.4.0**（2026-10-31）

---

## 0.4.0 · 2026-10-31

这一版基本把"能用"变成"敢用"：权限分档、长任务不丢、图文、成本可见、装完自检。

### 新增

| 功能 | 说明 |
|---|---|
| **前缀直连** | 配置页开关。打开后发 `/dsh <要做的事>` 直接执行，不再经过模型判断。前缀可改（`trigger_prefix`），改 `!dsh` 也行 |
| **图片** | 消息里的图片转 base64 一并交给 DSH（最多 4 张、单张 6MB），走 `attachments.admitPromptContent` 变正式图片块 |
| **长任务不丢结果** | 超过 `timeout` 自动转后台，跑完**补发一条消息**到原聊天（`job_max_wait` 控制追多久，默认 600 秒） |
| **权限分档** | 管理员拿全部工具；其他人只拿白名单（`guestAllow` 前缀）。用引擎的 `tools.restrict` + `guard`，是工具级隐藏，不是提示词约束 |
| **禁用工具** | `denyTools` 对所有人生效，默认禁 `bili_run` |
| **值班关键词** | 消息里出现 `值班` / `日报`（可配 `duty_keywords`）时，才对**这一轮**临时放行 `bili_run`，跑完收回 |
| **预热** | DSH 启动 3 秒后预建绑定表里的会话，省掉首轮那 60 秒 |
| **工作区登记** | 把工作目录登记进侧栏，会话不再"凭空"存在 |
| **用量统计** | 按轮累计 token（输入/输出/缓存命中），`/state` 可取，`/dsh` 卡片上直接显示 |
| **配置页** | AstrBot 插件页有了正式表单：模式、超时、绑定、自动推送、管理员放行、前缀直连、值班关键词，每项都带说明 |

### 修复

| 问题 | 后果 | 原因 |
|---|---|---|
| `dataclass(config=...)` 用了标准库 | **插件根本没加载**，模型只能凭想象回"我碰不到电脑" | 应该用 `pydantic.dataclasses.dataclass` |
| 配置里中文被写成乱码 | key 变成 `鑲ラ奔…`，绑定全失效 | 请求体逐 chunk `toString()` 把跨包的汉字切坏；改成先收 Buffer 再统一解码 |
| 值班放行永远不生效 | 说了"值班"也调不动 `bili_run` | 放行表用"去掉 `session-`"的键存，guard 用带前缀的 id 查 |
| 管理员被砍成 14 个工具 | `pwsh` 等能力消失 | 对管理员误用了「允许清单」；改成「只按名字拒绝」 |
| 用量被别人的会话污染 | 总账多出 118 万缓存读 | 统计了宿主所有会话；改成只统计桥接发起的那一轮 |
| `bili_run` 双跑 | 一次任务刷两遍、双倍额度 | 它会在后台另起 headless 会话；加了 `denyTools` |

### 变更

- 配置文件从"手改 JSON"变成"插件页表单"；改完自动推给 DSH（`auto_bind`）。
- `install.ps1` 现在会自动往 DSH profile 的 `dependencies` 与 `dsh.profile.bundles` 里补条目（改前备份）。
- 聊天里新增 `/dsh`（自检卡片）、`/dsh help`、`/dsh bind <session-id>`。

## 从旧版升级

1. 覆盖两个插件目录（或跑 `install.ps1`）
2. 重启 DSH；AstrBot 重载或重启
3. 打开插件配置页确认：`bindings` 还在、`admin_full_access` 开着、`prefix_direct` 按需
4. 发 `/dsh` 看一眼卡片，全绿就没事

**不需要**重装依赖，也没有数据结构变更——配置文件向后兼容，缺的字段会用默认值补上。

## 已知限制

- 超时只能转后台等，**没有"中断某一轮"的接口**（引擎不提供）
- 只能"派任务"，不能精确指定"调哪个工具"
- 图片只支持传**入**，DSH 产出的图片不会自动发到 QQ
- 工作会话由插件自建，侧栏里能不能看见取决于 UI 分组
- `bili_run` 的价值和代价都在它自己身上：完整日报 vs 双倍开销
